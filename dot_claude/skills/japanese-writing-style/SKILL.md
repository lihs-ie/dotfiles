# japanese-writing-style

日本語のまとまった文章に適用する文体ルール。読点の乱用と冗長な「Aは、B。」構文を排除し、
切れ味のある読みやすい文章にする。

読点が多い文章は一見丁寧に見えるが、実際には文の骨格を分断して読み手の負荷を上げる。
読点を「意味の切れ目にだけ」置くと、残った読点が構造を示す信号として機能するようになる。
これがこのルール全体の狙い。

## ルール

### 1. タイトル・見出しは体言止め

| NG | OK |
|----|----|
| `# 検索基盤を移行します` | `# 検索基盤の移行` |
| `## テストを実行する` | `## テスト実行手順` |
| `## なぜ移行するのか。` | `## 移行の理由` |

見出しに「。」を使わない。「〜します」「〜する」で終わる見出しは名詞句に組み替える。

### 2. 本文の「Aは、B。」構文を原則禁止

主題の「は」の直後に読点を置かない。

- NG: `現行の検索基盤は、応答速度が劣化している。`
- OK: `現行の検索基盤は応答速度が劣化している。`

直し方は 3 通り。文脈に合うものを選ぶ:

1. **読点だけ削る** — 文が短ければこれで足りる (上の例)
2. **名詞句・体言止め化** — `結論は、移行の延期。` → `結論: 移行の延期`
3. **構文の組み替え** — 主題が長く読点を削ると読みにくい場合、文を分割するか語順を変える

### 3. 助詞直後の不要な読点を入れない

「Aを、Bする」「Aが、Bになる」「Aで、Bする」は、誤読防止の必要がない限り
「AをBする」「AがBになる」「AでBする」に直す。

- NG: `インデックスを、毎晩再構築する`
- OK: `インデックスを毎晩再構築する`

### 4. 読点を置いてよい場所

読点は次の場合のみ使用する:

- **意味の切れ目**: 接続詞・接続句の直後 (`ただし、` `一方、` `その結果、`) と条件節の直後 (`障害が発生した場合は、`)
- **並列**: `検索、集計、監視の各機能`
- **長文の誤読防止**: かかり先が曖昧になる場合。例: `昨年から段階的に進めてきたスキーマ正規化の作業が、今回の移行の前提になる` — 長い主語の切れ目を読点で示す

### 5. 箇条書きの「**ラベル**: 説明」形式の禁止

`- **ラベル**: 説明文` の形を使わない。太字ラベルと説明の詰め込みは AI 出力特有の紋切り型で、
項目が増えると太字だらけになり視認性が下がる。ラベルを親項目、説明を子項目に分ける。

NG:

```markdown
- **誤デプロイ**: 承認ゲートで防止する
```

OK:

```markdown
- 誤デプロイ
  - 承認ゲートで防止する
```

### 6. 一文一行

本文の「。」の後は必ず改行し、1 行に 1 文だけ置く。Markdown では単一改行が表示上連結されるため
見た目は変わらず、diff・レビュー・文単位の修正がしやすくなる。

NG (1 行に 2 文):

```markdown
現行の検索基盤は応答速度が劣化している。バッチがピーク時間帯と重なっているためだ。
```

OK:

```markdown
現行の検索基盤は応答速度が劣化している。
バッチがピーク時間帯と重なっているためだ。
```

## 出力前の全件確認

出力前に「は、」「を、」「が、」「で、」「など、」を全件確認し、不要な読点を削除する。

ファイルに書き出す場合は同梱スクリプトで候補を機械列挙する:

```bash
scripts/check-style.sh <file.md> [<file.md>...]
```

- 出力形式: `file:行番号:種別:該当行`
- 種別: `comma` = 助詞直後の読点 / `heading` = 見出し文体 / `boldlabel` = 太字ラベル箇条書き / `newline` = 「。」後の改行なし
- exit 0 = 候補なし / exit 1 = 候補あり / exit 2 = 引数・ファイルエラー
- コードフェンス (``` 区間) の内側はスキップする

候補は**違反確定ではない**。接続句 (`ここでは、` `一方で、`)・条件節 (`〜場合は、`)・誤読防止に
必要な読点もヒットするし、`newline` は `。」` や表のセルにも反応する。
各候補をルール 4〜6 に照らして判定し、残す場合は理由を言えること。

会話応答などファイルに書き出さない出力では、スクリプトの代わりに送信前へ同じ全件走査を自分で行う。

## ワークフロー

### 文章を書くとき (生成)

1. ルール 1〜6 を守って書く
2. `check-style.sh` (ファイルでない場合は目視の全件走査) で候補を確認する
3. 不要な読点を削除してから出力する

### 既存文書を直すとき (校正)

1. `check-style.sh` で候補を列挙する
2. 各候補をルール 4〜6 に照らして判定し、不要なものだけ直す。**意味・内容は変えない**
3. 再実行し、残った候補が全て「意図して残した読点」であることを確認する
4. 修正の一覧と、残した読点それぞれの理由を報告する
