# Workspace Resume

並行プロジェクトの文脈復元コスト（「どこまでやったか」を思い出す時間）をゼロに近づける。

原則: **記憶を人間の頭からファイルに移す**。再開情報の正本は各リポジトリの `HANDOFF.md`。
git ログ・TODO・PR は補助証拠であり、HANDOFF.md が最優先。

## モード判定

| ユーザーの発話 | モード |
|---|---|
| 「今日何する」「全体の状況」「どのプロジェクトやるか」 | dashboard |
| 「<project> を再開」「<project> どこまでやったっけ」 | resume `<project>` |
| 「引き継ぎ書いて」「handoff 保存」「今日はここまで」 | save |

## dashboard モード

```bash
bash ~/.claude/skills/workspace-resume/scripts/scan.sh
```

出力 (`|` 区切り) を Markdown 表に整形して提示する。列: 最終コミット / リポジトリ / ブランチ / 未コミット数 / ahead-behind / HANDOFF 有無。

提示後に必ず **「再開推奨」を 1〜3 個** 挙げる。判断基準（優先順）:
1. dirty > 0（やりかけで放置 — 最優先で回収）
2. HANDOFF.md があり「次の一手」が未消化
3. 最終コミットが最近（勢いがある）

## resume モード

```bash
bash ~/.claude/skills/workspace-resume/scripts/scan.sh <repository-name>
```

出力を読み、**再開ブリーフ**を以下の形式で合成する（長文ダンプの転記は禁止。合成すること）:

```markdown
## 再開ブリーフ: <repository>
- **現在地**: <branch / 最終コミット / 未コミットの状態を1文で>
- **前回の作業**: <直近コミット列と HANDOFF から1〜2文で>
- **注意**: <未コミット・stash・open PR・古い HANDOFF 等のリスク。なければ「なし」>
- **次の一手 (候補)**:
  1. <HANDOFF の「次の一手」から>
  2. <TODO / open PR から>
  3. <コミット軌跡からの推論>
```

情報源の優先度: HANDOFF.md > TODO > open PR > コミット軌跡。矛盾したら HANDOFF.md の日付と
最終コミット日を比べ、**HANDOFF が古い場合はその旨を「注意」に明記**する。

ブリーフ提示後、「どれから始めるか」をユーザーに確認してから作業に入る。

## save モード

セッション終了時（または区切りがついたとき）に、対象リポジトリ直下の `HANDOFF.md` を更新する。

手順:
1. 現在のセッションで実際にやったこと（会話履歴と `git log` / `git status`）を確認する
2. 既存 `HANDOFF.md` があれば **必ず Read してから** 以下のテンプレートで更新（上書き前に差分方針を一言添える）
3. セッションログは **最新 10 行のみ保持**（古い行は削除）

```markdown
# HANDOFF — <repository>

最終更新: <YYYY-MM-DD>

## 現在地
<1 段落: いまどのフェーズで、何が動いていて、何が動いていないか>

## 次の一手
- [ ] <具体的なアクション（着手可能な粒度）>
- [ ] ...

## 注意・ブロッカー
- <未解決の問題、待ち状態、壊れているもの。なければ「なし」>

## セッションログ (最新10件)
- <YYYY-MM-DD>: <1 行でこの日の成果>
```

書き込み後、コミット対象にするか確認する（推奨: `docs(<repository>): update HANDOFF` で
コミット。複数マシン間・セッション間で正本になるため）。

## 禁止事項

- scan.sh の生出力をそのまま貼らない（合成して 5 行ブリーフにする）
- HANDOFF.md を Read せずに上書きしない
- 「次の一手」を空にしない（最低 1 個。本当に完了なら「完了 — リリース/アーカイブ判断待ち」と書く）
